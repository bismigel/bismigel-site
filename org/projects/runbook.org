This is the *how*, not the *what*. The reference explains the design and why it
looks like this; this page is what to type when something needs to change, and
the one gotcha that turns a five-minute change into an evening.

* 0. Before you start

** Conventions

- `platform` = the AMD node (control plane, ArgoCD, ingress, cloudflared).
- `media` = the Intel node (media stack, QuickSync, `/mnt/media`).
- `etcd` = the MacBook (etcd quorum, Immich data).
- `zone` = the Cloudflare zone. `tunnel` = the remote-managed Cloudflare Tunnel.
- `<name>`, `<host>`, `<provider-host>`, `<zone-id>` are placeholders; the real
  values are in the private context repo and Bitwarden.

** Access

- **Cluster:** `ssh root@platform` then `sudo k3s kubectl …` (the kubeconfig is
  `0600`, so on-host kubectl is root-only).
- **ArgoCD:** `argocd.bismigel.dev`, behind Cloudflare Access.
- **OS:** from `nix-station`, `nix run github:serokell/deploy-rs -- .#<host>`.
- **OpenTofu:** runs on `platform` (token and R2 credentials live there).
- **Secrets:** Bitwarden Secrets Manager (machine, project `homelab-kube`) and
  SOPS/age (host).

** Golden rules

1. **Pull requests only.** Branch, PR, review, merge. Never push `main`.
2. **GitOps.** Change `bakuran-gitops` (or the app repo), never hand-edit
   resources ArgoCD owns. If ArgoCD didn't apply it, it did not happen.
3. **No secrets in git.** Ever.
4. **Cloudflare writes are guarded.** Reads are fine; a DNS/tunnel/Access/WAF
   change is a human, reviewed step.
5. **Ask before destructive.** Cluster changes, deletes, data loss.
6. **Cite the source** of a fix (issue link or docs) in the PR.

** "Is it healthy?" in four commands

#+begin_src sh
kubectl get nodes
kubectl -n argocd get applications | grep -v 'Synced.*Healthy'
kubectl -n kube-system exec ds/cilium -c cilium-agent -- cilium-dbg status | grep 'Cluster health'
ssh root@platform 'systemctl start homelab-smoke; systemctl show -p Result --value homelab-smoke'
#+end_src

`homelab-smoke` checks nodes, ArgoCD, Cilium, the public site and the media
hostPort; it runs every 15 minutes and alerts on failure.

* 1. Add a new public hostname (FQDN)

A public name touches three layers: the app's Ingress, the Cloudflare tunnel
route, and (for admin names) an Access application.

** 1.1 The Ingress (GitOps)

Add the Ingress in the app's Kubernetes manifests (or `bakuran-gitops`), class
`nginx` for public names, `nginx-admin` for anything behind Access:

#+begin_src yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: myapp
  namespace: apps
spec:
  ingressClassName: nginx
  rules:
    - host: myapp.bismigel.dev
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: myapp
                port:
                  number: 8080
#+end_src

** 1.2 The tunnel route (Cloudflare)

The tunnel is **remote-managed**: routing lives in the Cloudflare dashboard/API
and cloudflared pulls it. Add a public hostname pointing at the ingress:

#+begin_src text
myapp.bismigel.dev  ->  http://127.0.0.1:32080
#+end_src

The `services.cloudflared` ingress map in the NixOS config is a *reference
fallback only* — keep it roughly in sync, but the dashboard/API wins. DNS and
the proxied CNAME to the tunnel are created there too. This is a guarded write:
do it deliberately, then verify.

** 1.3 Access vs public

- **Admin names** (grafana, argocd, prometheus, the *arrs, …) sit on the
  `nginx-admin` controller and a Cloudflare Access application.
- **Public names** (jellyfin, immich, kavita, the static site) have no Access;
  they rely on the application's own login.

Pick deliberately. A name with no auth and no Access is public forever.

** 1.4 Verify

#+begin_src sh
dig +short myapp.bismigel.dev
curl -s -o /dev/null -w '%{http_code}\n' https://myapp.bismigel.dev/
#+end_src

** 1.5 Gotchas

- **Rate limiting** applies to the public controller; Jellyfin is exempt (empty
  `limit_req` key). Admin names are behind Access and not limited.
- **Free Cloudflare plan**: Access and custom WAF rules are included; rate
  limiting and managed WAF are not.
- **isTLS at the edge.** Cloudflare terminates TLS; the origin leg is HTTP and
  no Ingress uses `tls:`.

* 2. Add a Usenet provider

The provider is two changes: SABnzbd's server list, and the pod's egress policy
(the one that bites).

** 2.1 Credentials

Store the provider username/password (and any API key) in Bitwarden Secrets
Manager. Never in a manifest.

** 2.2 SABnzbd

Config → Servers → add the host, port, TLS and credentials. Typical: NNTP over
TLS on `563` (alternates `443`, `119`). Save and use **Test Server**.

** 2.3 Egress (the important part)

SABnzbd runs under default-deny egress. Add the provider's networks to
`bakuran-gitops/manifests/network-policies/downloads-egress.yaml`:

#+begin_src yaml
    - toCIDRSet:
        - cidr: <provider-cidr>       # new provider
        - cidr: 62.164.182.0/24       # Frugal (example)
      toPorts:
        - ports:
            - { port: "563", protocol: TCP }
            - { port: "443", protocol: TCP }
            - { port: "119", protocol: TCP }
#+end_src

Find the CIDRs from the provider's hostname (RDAP, not guesswork):

#+begin_src sh
getent ahostsv4 <provider-host> | awk '{print $1}' | sort -u
curl -sL https://rdap.org/ip/<one-of-those-ips> | jq -r '.cidr0_cidrs[].v4prefix'
#+end_src

**Why CIDRs and not `toFQDNs`?** The cleaner form is a Cilium FQDN allowlist, and
it now works — *if* the DNS rule carries an L7 rule:

#+begin_src yaml
    - toEndpoints:
        - matchLabels:
            io.kubernetes.pod.namespace: kube-system
            k8s-app: kube-dns
      toPorts:
        - ports: [{ port: "53", protocol: ANY }]
          rules:
            dns: [{ matchPattern: "*" }]     # without this, toFQDNs is a no-op
    - toFQDNs:
        - matchPattern: "*.example-provider.com"
      toPorts:
        - ports: [{ port: "563", protocol: TCP }]
#+end_src

CIDRs are kept because they are DNS-proxy-independent and simple; add the new
provider's ranges and you are done. If the provider rotates, update the list.

** 2.4 Verify

#+begin_src sh
# from the SABnzbd pod (replace the IP with one the provider resolves to)
kubectl -n downloads exec deploy/sabnzbd -- \
  bash -c 'timeout 6 bash -c "echo > /dev/tcp/<provider-ip>/563" && echo OK || echo FAIL'
# and watch the policy verdict
kubectl -n kube-system exec ds/cilium -c cilium-agent -- \
  hubble observe --namespace downloads --since 2m --output compact | tail
#+end_src

** 2.5 Gotchas

- **Default-deny.** A missing CIDR means "connection timed out", not "denied".
  Test from the pod, not from the host — the host bypasses the policy.
- **`toFQDNs` needs the L7 DNS rule** (`rules.dns`). Without it the proxy never
  learns IPs and everything is denied.
- **`accept_local`.** On a node where something sets
  `net.ipv4.conf.all.src_valid_mark=1` (a WireGuard interface), Cilium's
  transparent DNS proxy drops the marked packet as a martian source unless
  `accept_local=1` on the pod veth. The NixOS config pins this.
- **IPv4/IPv6.** The cluster is IPv4-only; a provider that answers AAAA first
  can look like a broken connection when tested with a v6-preferring tool.

* 3. Jellyfin accounts

** 3.1 Preferred: the script

`media-stack-setup.sh` has an idempotent helper that authenticates as admin,
checks for the user and creates it only if missing:

#+begin_src sh
# run from nix-station, on the media host; needs the admin creds in the
# media-setup Secret (seeded from Bitwarden)
ensure_jellyfin_user <name> "<password>"
#+end_src

** 3.2 The API, if you must

#+begin_src sh
J=http://<media>:8096
AUTH='Authorization: MediaBrowser Client="setup", Device="setup", DeviceId="setup", Version="1.0.0"'
TOK=$(curl -s -X POST "$J/Users/AuthenticateByName" -H 'Content-Type: application/json' \
      -H "$AUTH" -d "{\"Username\":\"<admin>\",\"Pw\":\"<admin-password>\"}" | jq -r .AccessToken)
curl -s -X POST "$J/Users/New" -H 'Content-Type: application/json' \
  -H "Authorization: MediaBrowser Token=$TOK" \
  -d "{\"Name\":\"<name>\",\"Password\":\"<password>\"}"
#+end_src

Then set library access / policy (dashboard, or `POST /Users/<id>/Policy`).

** 3.3 Store the password

Add it to Bitwarden Secrets Manager as `jellyfin-<name>`, seed it into the
in-cluster `media-setup` Secret (the seed script), and add it to the personal
vault if a person will use it.

** 3.4 Disable / remove

Disable in the dashboard (user → disable), or flip `IsDisabled` on the user
policy; delete for a real removal. Locking a *command* (`!lock`) is different —
that is the bot, not a Jellyfin user.

** 3.5 Gotchas

- **Jellyfin 12.x header:** `Authorization: MediaBrowser …` is required.
  `X-Emby-Authorization` returns **400**.
- **Not a Playback config:** `RemoteClientBitrateLimit` lives in
  `ServerConfiguration` → `GET/POST /System/Configuration`; there is no
  `/System/Configuration/Playback`.
- **Non-root:** the server runs as UID 1000, not root; config and cache are
  chowned by an init container.
- **GPU:** the iGPU is a device-plugin resource (`gpu.intel.com/i915`); the
  container is not privileged.

* 4. Immich: signup, users, sessions

Immich is **public** (no Cloudflare Access — the native apps cannot do the
email-OTP), so its own login is the only gate. Keep signup **off**.

** 4.1 Turn signup off (and on)

In the admin UI: **Administration → Settings → User Registration** ("Allow new
users to sign up"). Off is the default posture here. The same setting is
available over the API (`PUT /api/system-config`, admin token); confirm the
exact field name against your version's API page before scripting it.

** 4.2 Create a user**

Administration → Users → Create (or the API). Give it a real email and a
password from Bitwarden; the login watcher will then surface failures.

** 4.3 Watch logins**

The `immich-login-watch` CronJob posts new-session rows to Alertmanager. If
logins look wrong, check `kubectl -n monitoring logs job/immich-login-watch-*`.

** 4.4 Gotchas

- **It is public.** With signup on, anyone who finds the hostname can create an
  account. Off is not optional.
- **Sessions/backups:** the Postgres DB and photo library live on `etcd`'s
  `/mnt/data/immich` and are included in the R2 backup.

* 5. Deploying changes

** 5.1 An application

Push to the app's `main`. CI builds the image, pushes to GHCR, bumps the tag;
ArgoCD rolls it out. A docs-only commit should not rebuild an image.

** 5.2 GitOps manifests

Open a PR against `bakuran-gitops`, merge, and let ArgoCD sync. If you need it
now:

#+begin_src sh
kubectl -n argocd annotate application <app> argocd.argoproj.io/refresh=normal --overwrite
#+end_src

** 5.3 The OS (NixOS)

#+begin_src sh
nix run github:serokell/deploy-rs -- .#<host>
#+end_src

Canary order for a cross-node change: **etcd → media → platform** (quorum
survives losing one member), verifying between each.

** 5.4 Gotchas

- **kubeconfig is 0600:** on-host `kubectl` needs root.
- **A deploy runs `systemd-sysctl`:** pin anything k3s needs (IPv4 forwarding)
  or it is reset and the cluster loses pod egress until a reboot.
- **ArgoCD + Jobs:** a `ttlSecondsAfterFinished` on a Job ArgoCD manages makes
  it re-run forever (selfHeal recreates it); Job pod templates are immutable, so
  a change needs a new name or a delete-then-sync.

* 6. Secrets

- **Machine secrets:** Bitwarden Secrets Manager → External Secrets Operator
  (or the `media-setup` seed script for namespaces without ESO).
- **Host secrets:** SOPS/age, decrypted on the host from its SSH host key.

** Add a secret

1. Create it in Secrets Manager (`homelab-kube`).
2. Reference it from an `ExternalSecret` (or seed it with the media script).
3. Sync/reconcile and confirm the consumer picked it up.

** Rotate a secret

Update the source (Secrets Manager or SOPS), reconcile/restart the consumer, and
verify. `bw` sessions are per-process: a terminal that unlocked the vault does
not unlock another process, which needs `BW_SESSION`.

* 7. Backups and recovery

- **Daily:** host keys, kubeconfig, and app data are backed up to R2
  (`homelab-backup.service` on the hosts, `backup-apps` for the apps).
- **Restore drills:** a backup that has never been restored is a hypothesis.
  Run the documented restore check and record the result.
- **NFS boot order:** bring `platform` up before `media`. If `media` boots first
  the remote mounts fail and the media pool does not come up.
- **Full rebuild:** `bakuran-infra/docs/REBUILD.md` plus the R2 credentials
  backup. Keep the offline copy of the age key somewhere it can actually be
  reached.

* 8. When something is wrong

** First, localise

#+begin_src sh
kubectl get nodes
kubectl -n <ns> get pods -o wide
kubectl -n argocd get application <app>
kubectl -n kube-system exec ds/cilium -c cilium-agent -- cilium-dbg status
#+end_src

** Sharp edges worth remembering

| Symptom                                   | Likely cause / fix                                                        |
|-------------------------------------------+---------------------------------------------------------------------------|
| Pod can't reach a public host             | Egress allowlist (CIDR/FQDN); test from the pod, not the host             |
| DNS fails from a pod on one node only     | `src_valid_mark=1` + `accept_local=0` → set `accept_local=1` (DNS proxy)   |
| Whole cluster loses egress after a deploy | `systemd-sysctl` reset IPv4 forwarding; pin it on                          |
| ArgoCD Job re-runs every few minutes      | `ttlSecondsAfterFinished` + selfHeal; drop the TTL                        |
| Job can't be updated                      | Pod template immutable; rename or delete then sync                        |
| Jellyfin API returns 400                  | Use `Authorization: MediaBrowser …`, not `X-Emby-Authorization`           |
| Media writes fail over NFS                | mergerfs runs as root; `root_squash` is not safe here                     |
| Public hostname returns 429               | Ingress rate limit (Jellyfin is exempt); tune burst/rate                  |
| `kubectl` permission denied on a host     | kubeconfig is 0600; run as root/sudo                                      |
