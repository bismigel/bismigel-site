This is the reference document: the thing I wish existed when I started. It
describes *what* runs, *why* it is shaped that way, and *how* it fails. Where a
component has a sharp edge, the edge is written down.

* 0. Why "Bakuran"

In Tagalog, *bakuran* is the yard or enclosure around a house, from *bakod*, a
fence. It is the space behind the house where things get built, repaired, and
occasionally taken apart to see how they work.

That is exactly what this is: a fenced-off corner of the house for experiments.
It is personal, small, and safe to break on purpose. The name is a reminder that
this is a backyard, not a data centre, useful precisely because it is allowed to
be a little messy, as long as the messy parts are understood and written down.

* 1. Goals and constraints

The lab exists to be **useful** and to be a place to practise operations on real
failures. The constraints shaped almost every decision:

- *Three old machines in the cluster, plus a laptop as the staging host, no rack,
  residential power and internet.* High availability is desirable, but high *cost*
  is not.
- *One operator.* Anything that needs a human at 3am must page; anything that
  needs a human every week must be automated or removed.
- *Everything must be rebuildable.* A machine can die and the lab should come
  back from declarative state plus backups.
- *The edge is the only door.* No inbound ports; Cloudflare Tunnel is the sole
  path from the internet.

The MacBook was the third etcd member until 2026-10-28, when the ThinkCentre
replaced it (the swap has its own blog post). It then rejoined as a worker, found
the two things that had been living on it, and left the cluster for good: a 2012
laptop on permanent charge is a battery waiting to become a fire and a disk
waiting to fail, and it could not be recovered without someone physically opening
the lid. It now hosts the throwaway KVM guests used to rehearse changes that
could strand a node. The alternative — keeping it as a tainted quorum member —
was a worse failure mode than moving the role to hardware that can be reached
over SSH.

* 3. Network and edge

The LAN is flat and boring. Every host is static; there is no VLAN segmentation.
That is a known trade-off: simplicity now, a segmentation project later.

The **public edge is Cloudflare Tunnel**, not port forwarding:

- One tunnel, two connectors (platform + media) for redundancy.
- Every public hostname is a proxied CNAME to the tunnel; the tunnel routes to
  ingress-nginx bound to **loopback-only** NodePorts. There is no externally
  reachable NodePort.
- TLS is terminated at Cloudflare; the origins speak HTTP inside the cluster.
- *Zero Trust Access* gates admin and personal apps with email OTP and per-app
  session lengths (short for admin, long for media devices).
- **Public exceptions** are deliberate: Jellyfin, Immich, Karakeep and Kavita
  have their own authentication, and their native clients cannot complete an
  interactive Access challenge. They are exposed behind the user's own login
  instead. This is the single biggest security trade-off in the design and it is
  documented rather than hidden.
- Minimum TLS 1.2 and Bot Fight Mode are enforced from the same OpenTofu
  configuration that declares the tunnel routes, DNS records and Access
  applications (details in §6). Nothing on the edge is clicked into a dashboard.

* 4. The cluster

One **k3s cluster with three embedded-etcd members**, not three clusters. This
is the most important simplification in the lab: one API server, one ArgoCD, one
set of CRDs, one place to look.

- Kubernetes v1.36.5+k3s1, containerd, Cilium VXLAN with kube-proxy.
- Three server nodes, no taints: platform, media and quorum. Roles are enforced
  by nodeSelector, not by the scheduler refusing work.
- Workloads are pinned where their hardware lives: media on the Intel box for
  QuickSync and local storage, Immich's Postgres and Redis on the ThinkCentre,
  platform pieces wherever they land.
- Ingress runs with two replicas; cloudflared connectors run on two nodes.
- NodePorts are loopback-only by design; the LAN path exists only for the media
  UIs (Jellyfin/*arrs) because those apps refuse no-auth remote access but are
  comfortable on the LAN.

* 5. Storage

There are three storage stories, and confusing them is how data gets lost.

**Cluster storage (Longhorn).** Application config and databases live on
Longhorn volumes with two replicas: 17 volumes, 89 GiB provisioned, 178 GiB
scheduled once both copies are counted. This is for state that must follow a pod
to another node — ArgoCD, monitoring, app configs, small databases.

Five disks back it on three nodes:

| Node | Disk | Path | Capacity |
|------+------+------+----------|
| platform | default | =/var/lib/longhorn= (inside the OS filesystem) | 98 G |
| media | default | =/var/lib/longhorn= (inside the OS filesystem) | 98 G |
| quorum | default | =/var/lib/longhorn= (inside the OS filesystem) | 98 G |
| quorum | =data= | =/mnt/data=, a dedicated partition | 134 G |
| platform | =nvme= | =/mnt/media-nvme=, a dedicated partition | 340 G |

The two dedicated partitions exist because the auto-registered default disk on
every node lives inside =/=, the filesystem that carries etcd and the container
image store. On 2026-10-30 that was visible as the failure it is: one node had
120 MiB of room for the next replica while logging 43% usage, because the alert
compared usage to capacity and the scheduler decides on (free space - scheduled).
A recording rule now exports that ratio per disk, and two alerts sit on it at 90%
and 100%. Moving the remaining ~100 GiB off the OS filesystems is the open item in
§18.

**Media pool (mergerfs).** Three branches across two hosts are unioned into a
single 826 G pool, 483 G free: two local partitions on the media host and one
partition on the platform host exported over NFS. It was four branches until
2026-10-28, when an empty one was retired and became the dedicated Longhorn disk
above. Media is re-downloadable and *not* backed up: the backup budget goes to
configuration, credentials and photos, not to Linux ISOs and TV episodes.

**Photo store (Longhorn).** Immich's library (30 GiB) and Postgres (10 GiB) are
Longhorn volumes, so the pair can reschedule between nodes. Only the
machine-learning cache stays on =local-path=, because it is rebuildable. Backed
up as a database dump plus a file-level archive, not by replicating the disk.

* 6. GitOps and delivery

Everything that can be declared is declared. There are **four pipelines**, and they
use different tools on purpose, because they have different blast radii:

| What | Tool | State lives in | A deploy is |
|------+------+----------------+-------------|
| Cluster workloads | ArgoCD | git (=bakuran-gitops=) | a pull, with self-heal and prune |
| This website | GitHub Actions → GHCR | git (=bismigel-site=) | an image tag bump PR, then ArgoCD |
| Hosts (NixOS) | deploy-rs | git (=bakuran-infra=) | a push over SSH, with magic rollback |
| Cloudflare edge | OpenTofu | R2, =opentofu/cloudflare/terraform.tfstate= | =tofu apply= from the platform node |

#+begin_src mermaid

  IMG -->|workflow bumps the tag| GIT["GitOps repo<br/>manifests + image tag"]
  GIT --> ARGO["ArgoCD<br/>auto-sync · self-heal · prune"]

  BUILD --> IMG

  INFRA["bakuran-infra<br/>NixOS config"] --> DEP["deploy-rs<br/>magic rollback"]
  DEP --> HOSTS["Hosts<br/>kernel · services · cloudflared"]

  TF["opentofu/cloudflare"] --> TOFU["tofu plan + apply"]
  TOFU --> CF["Cloudflare edge<br/>DNS · tunnel · Access · TLS"]

**Cluster workloads.** An app repo merges to =main=; GitHub Actions builds and
pushes an image to GHCR with an immutable tag; the workflow rewrites that tag in
the GitOps manifest, pushes a branch and opens a pull request; ArgoCD reconciles
the merged commit. CI writes only an image tag and never holds a kubeconfig — the
manifest is the only interface between CI and the cluster.

**This website.** The same shape with a build in the middle: =org/*.org= is the
source, =scripts/convert.sh= runs pandoc, hugo builds =public/=, the image is
pushed to GHCR as =main-<UTC timestamp>-<sha>=, and the workflow bumps
=deploy/k8s/deployment.yaml= in a PR that auto-merges. Manifest-only paths are
excluded from re-triggering the build, and runs are serialised so two concurrent
tag bumps cannot conflict on the same line.

**Hosts.** NixOS is built from =bakuran-infra= and deployed with =deploy-rs=, with
magic rollback. The OS is not managed by ArgoCD, deliberately: the cluster should
not be able to brick its own hosts.

**The edge.** Cloudflare is OpenTofu, state in R2 with native locking
(=use_lockfile=, no separate lock table), applied by hand from the platform node.
It replaced a daily =sync.sh= run that rewrote DNS, tunnel routes, Access
applications and zone settings imperatively, incrementally and unreviewably. The
migration was one import at a time, check with =plan= that the import produced no
diff, then apply. Two things did not import cleanly and are handled after the
import: Access application timeouts, and the R2 bucket lifecycle, which has no
import and had to be adopted instead. A four-line change is now a reviewable
diff, which is how turning off IPv6 compatibility at the edge became a small
commit rather than a dashboard edit nobody can audit.

Reproducibility rules that came out of real failures:

- Images are **pinned** when upstream publishes a stable version or digest.
  Prometheus, Grafana, KSM, node-exporter, Alertmanager, Karakeep, Immich, Kavita
  and qBittorrent are on fixed versions or digests. The LinuxServer *arr stack and
  a few other app images track =latest= or =develop=; that is a known
  reproducibility gap.
- Renovate proposes updates for the pinned set; a human reviews and merges.
- Direct pushes to =main= are blocked by a git hook on the admin workstation.
  Public repos also use branch protection; private repos on the free plan cannot,
  which is a known limitation.
- Rebuild steps that involve application UIs are scripted. The book stack has a
  single idempotent bootstrap command that recreates admin accounts, libraries
  and download clients.

* 7. Platform services

- *ingress-nginx*: the only HTTP entry from the tunnel; forwards client IPs.
- *cert-manager*: internal certificates; public TLS is at Cloudflare.
- *External Secrets Operator*: Bitwarden Secrets Manager is the source of truth;
  Kubernetes secrets are materialised from it. Host-level secrets use SOPS/age.
- *Monitoring*: Prometheus, Alertmanager and Grafana. Scrapes node-exporter,
  kube-state-metrics, Kepler (power) and the ArgoCD controller endpoints.
  - *Kepler*: per-node power/energy metrics; useful for capacity and for noticing
    a runaway transcode.
  - *ArgoCD*: Helm release `argocd`, chart `argo-cd` 10.10.5. Redis HA runs three
    Redis/sentinel pods and three HAProxy pods. The per-pod announce Services are
    made headless by a Helm post-renderer, because the chart otherwise puts
    sentinel behind a ClusterIP.
  - *Duwende*: in-cluster AI agent and SRE; read-only tools and guardrails. The
    namespace and the ArgoCD app are =duwende=; the upstream workload, image and
    dashboard still carry the Hermes name.
  - *Homepage*: a single landing page for every service.

* 8. Media platform

Jellyfin and the *arr stack run on the Intel host, pinned by nodeSelector so
transcoding uses QuickSync and media reads stay local.

- Sonarr (TV), Radarr (movies), Prowlarr (indexers), Bazarr (subtitles).
- qBittorrent for torrents (anime is torrent-first: Nyaa batches), SABnzbd for
  Usenet fallback.
- A host-level nftables kill switch forces all egress through ProtonVPN and
  blocks the internet if the tunnel drops. LAN and cluster traffic are exempt.
- Remote Jellyfin clients are capped at 12 Mbps per user; LAN clients are not.
  Jellyfin trusts the ingress and cluster networks as proxies so it can tell the
  difference.
- New media appears on a scheduled scan (mergerfs has no inotify semantics worth
  relying on).

* 9. Photos

Immich runs split: the server, Postgres and Valkey sit on the quorum node, the
machine-learning container runs wherever it lands, and the library itself is on
Longhorn. All of it moved off the MacBook in the 2026-10-28 migration, which is
also when the Postgres data directory was copied cold (a live copy is how you get
a database that looks fine until it does not). Photo backup from phones is the
primary use, so the public hostname is not Access-gated; Immich's own accounts
and app passwords are the control. Accounts mirror the family's Jellyfin users.

* 10. Books

Kavita (reading) and LazyLibrarian (acquisition) run on the media host, sharing
=/mnt/media/books=.

The pipeline is: LazyLibrarian searches Newznab (NZBGeek) → sends to SABnzbd
(category =books=) → post-processes completed downloads into =/books= → Kavita
scans the folder.

Sharp edges that are now codified:

- LazyLibrarian's SAB client fields are not enough; the *download method* must be
  enabled or every grab is silently dropped.
- The directory SAB reports back must exist inside LazyLibrarian, so both
  containers mount the same media tree.
- New authors' books default to =Skipped=; the setup sets =Wanted= so a new
  author is actually searched.
- Kavita's library must have **metadata enabled**, otherwise it derives series
  from filenames (=Title - Author.epub= → no series) and imports nothing while
  logging "Unable to parse any meaningful information".
- LazyLibrarian re-serialises its config on startup and drops sections it did not
  create. Its configuration is therefore driven through its real UI by a script,
  not by editing files.
- Kavita's account model needs the =Login= role; without it the account exists
  but login says "account is disabled". Account lock/unlock toggles that role.

The agent can acquire books through the media MCP: find an author, add them,
inspect wanted/snatched books, and queue/search individual titles. The
LazyLibrarian API is internal and keyed; the key is exactly 32 characters (the
app rejects anything else, quietly).

* 11. Bookmarks

Karakeep stores bookmarks and full-text search runs in Meilisearch. AI tagging
and summarisation use **local Ollama**: qwen3:8b for text and qwen3-vl:8b for
images. No bookmark content leaves the LAN. The public hostname is not Access-gated
because the mobile apps cannot do
the OTP flow; NextAuth is the gate.

* 12. The agent (Duwende)

*Why "Duwende"*

A duwende is a small household spirit in Philippine folklore, a little caretaker
of the home and yard. The lab already has a bakuran, so naming its resident
helper Duwende completes the metaphor. It is meant to be a helpful, slightly
mischievous presence in the yard, not a product name.

The agent is an in-cluster AI SRE. The namespace and ArgoCD app are `duwende`;
the upstream workload, image and dashboard still use the Hermes name, so a
=kubectl get pods -n duwende= shows =hermes-*= and that is expected, not drift.

It runs as a Deployment with a 10Gi PVC at `/opt/data` for config, sessions,
memory and cron. It uses DeepSeek `deepseek-chat`. The dashboard is
`agent.bismigel.dev` behind Cloudflare Access and basic auth; Telegram uses the
same bot with a single-user allowlist.

Tools:

- Kubernetes MCP with the `homelab-agent-read` ClusterRole: get, list and watch,
  with no Secrets.
- Prometheus MCP for queries.
- media MCP for the *arr and book stack: add, search and queue, with no delete
  tools.
- GitHub MCP plus `gh` with a repo-scoped token: branches and pull requests.
- Cloudflare reads through a GET-only proxy; writes return 403.

The context docs and `SOUL.md` are on the PVC. The daily 08:00 America/Toronto
report goes to Telegram. The agent's state is included in the appdata backup.

Guardrails:

- Kubernetes is read-only.
- Cloudflare writes are blocked outside the agent.
- The PR-only rule is a working rule, not a hard block; every branch gets review.
- Destructive work needs human approval, and secrets must not be written to logs.
- The agent runs inside the cluster, so it shares the failure domain. The external
  dead-man's switch and Alertmanager remain the primary path.

The design is described in the blog post
[[https://bismigel.dev/posts/2026-10-16-ai-in-the-lab/][AI in the lab]].

* 13. Observability and alerting

Prometheus scrapes the cluster and the edge paths that matter. Alerts route to
Telegram through Alertmanager, grouped so a single failure does not become ten
messages.

59 rules live in two ConfigMaps and 11 dashboards each answer one question. What
is watched:

- Node and target availability, disk fill, memory pressure.
- Longhorn: robustness per volume, and per disk the ratio of promised bytes to
  free bytes — the number that decides whether the next rebuild can fit. Bytes
  still held on an OS filesystem stay visible as a dashboard panel rather than an
  alert, because all three nodes keep a default disk and a permanently true
  invariant is a gauge, not a page.
- WireGuard handshake age and data path on the media node. node-exporter has no
  collector for it, so a host timer writes the textfile.
- The Cloudflare edge from a small REST exporter: tunnel and connector state,
  zones, TLS, and its own snapshot age, so a silent exporter is visible too.
- ArgoCD application drift and health (after 15 minutes).
- Logins to the edge and to Jellyfin/Immich (new sessions, not every request).
- Backups: unit failure, staleness (newest archive older than 36 hours), and a
  weekly **restore verification** (decrypt, =gzip -t=, full =tar -t=, SQLite
  integrity check on the app databases, =gzip -t= on the database dump).
- An external dead-man's switch on the admin workstation: if the public status
  endpoint is unreachable three checks in a row, Telegram gets a message; a
  recovery message follows.

The dead-man's switch runs outside the cluster on purpose. A monitor that lives
inside the thing it monitors is decoration.

* 14. Backups and disaster recovery

Two daily, age-encrypted streams go to Cloudflare R2:

- =credentials/=: host SSH keys (also the SOPS age identity), kubeconfig and the
  Bitwarden machine token. Kept 90 days.
- =appdata/=: config volumes and databases for the *arrs, Jellyfin, Grafana,
  Prometheus, Hermes, Immich (dump + library), Kavita, LazyLibrarian, Karakeep
  and Meilisearch. Kept 14 days.

Design decisions:

- A partial backup **fails the unit** instead of uploading something incomplete.
- Freshness is checked independently of the backup timer.
- Restore is verified weekly, not assumed.
- Media files are not backed up; they are re-downloadable. Photos are backed up
  because they are not.
- The age identity needed to restore is itself stored in the password manager and
  on the admin workstation.

The honest RPO is about a day for application state and credentials; the RTO is a
rebuild plus restore, measured in hours, not minutes.

* 15. Security posture

- *Secrets* live in Bitwarden Secrets Manager, materialised by External Secrets;
  host secrets use SOPS/age. Nothing sensitive is in git.
- *Edge*: no inbound ports, TLS 1.2 minimum, Bot Fight Mode, Access on admin
  surfaces.
- *Auth*: each public app uses its own login; accounts are non-admin by default;
  lockout is enabled.
- *Network*: ingress-only default deny in the app namespaces. Same namespace and
  ingress-nginx are allowed; cross-namespace rules are explicit. Egress is still
  open.
  Jellyfin keeps a LAN-only 8096 exception for TVs.
- *Supply chain*: pinned where practical, a weekly image scan, dependency updates
  via Renovate, and a human merge gate. The *arr stack, some app images and utility
  images are not pinned yet.
- *Change control*: pull requests only; the cluster self-heals; host changes go
  through =deploy-rs=.

Known gaps, stated plainly: no custom rate limiting on the free Cloudflare plan,
no image signing or SBOM yet, no full-cluster disaster-recovery rehearsal yet,
and one public login surface (Kavita) that is internet-facing.

* 16. Reproducibility

A rebuild has three layers:

1. *NixOS hosts*: =bakuran-infra=, deployed with =deploy-rs=; SSH keys, users,
   services and the edge reconciler are declared.
2. *Cluster*: =bakuran-gitops= in ArgoCD; every namespace, workload, secret
   reference, ingress and alert is a manifest.
3. *Application state*: restorable from the R2 backup, or recreated by scripts:
   the book stack has one idempotent bootstrap; the media stack has setup scripts
   for root folders, clients, indexers and users.

Pinned images where upstream allows, versioned scripts and dated documentation are
what make the next rebuild boring. That is the goal.

* 17. Failure modes that shaped the design

| Symptom | Root cause | Fix / rule |
|---------+------------+------------|
| Books downloaded but never imported | SAB completed into a path LazyLibrarian did not mount | Mount the same tree in both containers |
| Every grab silently dropped | SAB download method disabled | Enable it in the UI setup script |
| Kavita imported nothing | Library metadata disabled; series parsed from filenames | Enable metadata on the library |
| "account is disabled" on login | Missing =Login= role | Role is part of the invite flow; lock/unlock toggles it |
| Backup "succeeded" with missing data | Failed dumps only logged SKIP | Fail the unit before upload |
| No backup alert when the timer stopped | OnFailure cannot see a timer that never ran | Daily freshness check + external dead-man's switch |
| Backup never restored | Trust | Weekly automated restore verification |
| Drift alerts never fired | Scraped the ArgoCD Service; only the leader has app metrics | Scrape controller endpoints |
| Config rejected after restart | Manual YAML indentation | Validate configs before merge; prefer generated files |
| Image pull failures after pinning | Guessed tag (=v0.33.2= vs =0.33.2=) | Verify tags/digests before merging |
| Node stopped answering its own LAN address after a tunnel change | =wg-quick= rules got kernel-assigned priorities above =local=, from a boot race with Cilium's rule at 9 | Pin =pref 32765= and =pref 32764=, and never restart the tunnel to "fix" it |
| Jellyfin buffered for off-LAN clients only | IPv6 packet loss to the edge while the client preferred AAAA; Happy Eyeballs covers browsers, not TV apps | Turn IPv6 compatibility off at the edge, after measuring both families |
| A replica could not be placed while capacity looked free | The alert compared usage to capacity; the scheduler decides on free space minus promised | Per-disk ratio recording rule, alerts at 90% and 100% |
| A node came back advertising an address no peer could reach | k3s derived its node IP from the default route, which is the tunnel | Pin =--node-ip= and =--advertise-address= |
| Redis HA pod stuck in =Init:0/1= | The chart made each announce Service a ClusterIP, so sentinel monitored a VIP that never converged | Post-renderer sets =clusterIP: None= |
| The NixOS installer could not kexec | The live image set =kexec_load_disabled=1=, a one-way switch | Install Nix on the live system and run =nixos-anywhere --phases disko,install= |
| Removing a node left pods =Pending= | Node-local volumes, PV =nodeAffinity= and a nodeSelector in three objects | Move state to Longhorn first; treat the node name as an interface |

* 18. Known limitations and next

- Branch protection is on for public repos; private repos on the free plan still
  rely on the workstation hook. Moving the GitOps repo to a host with required
  checks (Forgejo) is planned and deliberately deferred.
  - HSTS is enforced at Cloudflare. Rate limiting and MFA on Access are limited by
    the free plan and the identity provider.
  - Zero-touch rebuild is not complete: bootstrap is one command, not zero.
  - SLOs cover the public probes and error budgets; internal services still rely on
    symptom-based alerts.
- **~100 GiB of Longhorn replicas still sit on the three OS filesystems**, inside
  =/var/lib/longhorn=. The dedicated disks exist and have room; what is missing is
  the evacuation. The ratio alerts exist so this stays visible, and the move is the
  next storage change.
- No secrets rotation schedule.
- Media is unbacked by design; the trade-off is documented, not solved.
- Full DR rehearsal (rebuild a host, restore everything) is still a manual plan.
