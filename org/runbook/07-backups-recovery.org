#+TITLE: Backups and recovery
#+SUMMARY: What is backed up, how to prove a restore, and the boot order that saves a reboot.
#+GROUP: Recovery

- *Daily:* host keys, kubeconfig, and app data are backed up to R2
  (=homelab-backup.service= on the hosts, =backup-apps= for the apps).
- *Restore drills:* a backup that has never been restored is a hypothesis.
  Run the documented restore check and record the result.
- *NFS boot order:* bring =platform= up before =media=. If =media= boots first
  the remote mounts fail and the media pool does not come up.
- *Full rebuild:* =bakuran-infra/docs/REBUILD.md= plus the R2 credentials
  backup. Keep the offline copy of the age key somewhere it can actually be
  reached.

* The restore log

What these entries establish, which the rest of this page only asserts:

- *R2 is readable* with the age key, on a machine that is not the cluster.
- *The tarballs restore into Longhorn PVCs* without a manual volume rebuild, once the
  PVC exists (creating the PVC is the part that needs the break-glass annotation).
- *A restored app can look healthy and be broken*: both failures above returned HTTP
  200. Verify function -- a login, a library count -- not liveness.
- *Boot order is real*: \=platform\= before \=media\=, or the remote mounts fail and the
  pool does not come up.
