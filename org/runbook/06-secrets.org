#+TITLE: Secrets
#+SUMMARY: Bitwarden Secrets Manager and SOPS: add, reference and rotate.
#+GROUP: Platform

- **Machine secrets:** Bitwarden Secrets Manager → External Secrets Operator.
  The store is a *ClusterSecretStore*, so **every namespace can use it** — "this
  namespace has no ESO" is never a reason to hand-write a Secret.
  Two objects are still seeded by a host script because a workload reads them
  before ESO could: `media/media-setup` and `media/usenet-frugal`.
- **Host secrets:** SOPS/age, decrypted on the host from its SSH host key.

* Add a secret

1. Create it in Secrets Manager (`homelab-kube`).
2. Reference it from an `ExternalSecret`.
3. Sync/reconcile and confirm the consumer picked it up.

Never `kubectl apply` a Secret by hand if the point is to make it exist: that is how
`books/kavita-secrets` and `books/lazylibrarian-secrets` ended up with no record of
whether they still matched Bitwarden. Both are ExternalSecrets now — see runbook 19.

* Rotate a secret

Update the source (Secrets Manager or SOPS), reconcile/restart the consumer, and
verify. `bw` sessions are per-process: a terminal that unlocked the vault does
not unlock another process, which needs `BW_SESSION`.
