#+TITLE: Secrets without plaintext
#+DATE: 2026-10-13
#+FILETAGS: security:homelab:secrets

Secrets were the thing I understood worst when I started, and the thing that
most often made me realise I didn't understand the rest either. The rule I've
landed on is simple — no secret sits in Git as readable text — but getting there
took a couple of wrong turns I want to record.

* In the cluster: Sealed Secrets

This is where I started. A controller in the cluster holds a private key, and the
matching public key encrypts:

#+begin_src shell
kubectl create secret generic app \
  --from-literal=KEY=value --dry-run=client -o yaml \
  | kubeseal --format yaml > sealed-secret.yaml
#+end_src

The output is safe to commit, and on sync the controller decrypts it into a real
Secret. I liked it because it felt self-contained. What I didn't grasp until I
had a second cluster was the line right after working:

Each cluster runs its own controller with its own sealing key, so a sealed secret
is sealed for the specific cluster that will run it — the same plaintext, sealed
for two clusters, is two different files. That's fine, until you lose a cluster
and its key with it.

* On the host: SOPS with age

Host secrets, like the tunnel credentials, stay encrypted in the NixOS repo and
get decrypted at activation, using the machine's own SSH host key as the age
identity. This one I've never wanted to change.

#+begin_src shell
sops secrets/homelab.yaml    # edit; re-encrypts on save
#+end_src

* The rule

Plaintext never enters Git. If a value has to live in the repo, it gets encrypted
first. I keep this simple on purpose, because every time I've made secrets
cleverer I've understood them less.

#+begin_quote
Back up the sealing keys. This is the lesson I learned the slow way — without
them, sealed secrets can't be opened again.
#+end_quote

* Since writing this

I moved the cluster half to a managed store: *Bitwarden Secrets Manager*, fronted
by *External Secrets Operator*. The values now live outside the cluster, so a
cluster wipe doesn't lose them, and rotating a credential means editing it there
instead of re-sealing a blob. The host half stayed on SOPS.

I'd love to say I reasoned my way to this, but what actually happened is the
two-cluster problem from Sealed Secrets forced my hand, and I found the managed
store was the thing that made the problem go away. The full thinking is in
[[file:2026-10-11-choosing-the-architecture.org][Choosing the architecture]].
