Secrets were the thing I understood worst when I started. They were also the thing
that most often showed me I didn't understand the rest. The rule I ended up with
is simple: no secret sits in Git as readable text. Getting there took a couple of
wrong turns, and I want to write them down.

* In the cluster: Sealed Secrets

This is where I started. A controller in the cluster holds a private key, and the
matching public key encrypts:

#+begin_src shell
kubectl create secret generic app \
  --from-literal=KEY=value --dry-run=client -o yaml \
  | kubeseal --format yaml > sealed-secret.yaml
#+end_src

The output is safe to commit. When it syncs, the controller turns it back into a
real Secret. I liked it because it felt self-contained. I didn't understand the
catch until I got a second cluster:

Each cluster runs its own controller with its own sealing key. So a sealed secret
only works for the one cluster it was sealed for. The same password sealed for two
clusters is two different files. That's fine until you lose a cluster and its key
along with it.

* On the host: SOPS with age

Host secrets, like the tunnel credentials, stay encrypted in the NixOS repo. They
get decrypted at activation, using the machine's own SSH host key as the age
identity. I've never wanted to change this one.

#+begin_src shell
sops secrets/homelab.yaml    # edit; re-encrypts on save
#+end_src

* The rule

Plaintext never enters Git. If a value has to live in the repo, I encrypt it
first. I keep it simple on purpose. Every time I've tried to get cleverer with
secrets, I've understood them less.

#+begin_quote
Back up the sealing keys. This is the lesson I learned the slow way — without
them, sealed secrets can't be opened again.
#+end_quote

* Since writing this

I moved the cluster half to a managed store: *Bitwarden Secrets Manager*, with
*External Secrets Operator* in front. The values now live outside the cluster, so
wiping a cluster doesn't lose them. To change a password I edit it there instead
of re-sealing something. The host half stayed on SOPS.

I'd like to say I worked this out by thinking it through. What really happened is
the two-cluster problem from Sealed Secrets forced me to do something, and the
managed store turned out to be what made the problem go away. The longer version
is in [[file:2026-10-11-choosing-the-architecture.org][Choosing the architecture]].
