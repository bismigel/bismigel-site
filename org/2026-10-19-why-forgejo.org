#+DESCRIPTION: The required-checks gap on GitHub Free, why that makes CI advisory on a private homelab repo, and the migration order I would follow if I moved to Forgejo.

I added CI to the GitOps repo. The workflow validates YAML, Kubernetes schemas and
Prometheus rules, and it runs on every pull request.

It still does not block a bad merge. =bakuran-gitops= is private on GitHub Free, and
required status checks and branch protection are paid features for private
repositories. The workflow can be red and the merge button still works. For a one-person
lab that is a discipline problem; as a public signal it is worse, because the repo would
advertise guardrails it cannot enforce.

* What I want from a Git host

A private remote I control; pull requests; required checks that actually block; no
per-seat or per-private-repo paywall; and a path to CI and an OCI registry I understand.

Forgejo is the obvious candidate. It is lightweight, self-hostable, and has branch
protection and Actions without GitHub's private-repo gate.

* What Forgejo does not solve

Running the server is the easy part, and the migration is the work:

- GitHub Actions are not guaranteed to run unchanged;
- a self-hosted runner is another privileged workload to secure;
- GHCR has to be replaced or kept external;
- repository imports do not guarantee perfect pull-request and issue history;
- SMTP, OAuth, TLS, backups and upgrades become mine;
- public Git access needs a different auth story from a browser app behind Cloudflare
  Access.

Forgejo gives control. It also gives me another service to patch.

* Why I am deferring it

I do not want to migrate the platform and the Git host in the same month. The honest
sequence is: finish the current platform work, run Forgejo internally with no public
edge, mirror two repos and read them from ArgoCD, port one CI workflow rather than all
of them, restore Forgejo from backup once, and migrate only after the mirror and the
restore are boring.

Until then the current CI stays, because it is useful even when it is advisory. The gap
between "a check ran" and "a check blocked the merge" is exactly what Forgejo would
close, and it is not worth closing in the middle of something else.
