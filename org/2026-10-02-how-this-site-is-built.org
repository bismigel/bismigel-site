I wanted a place to write without running a database or adopting a full CMS. The site
is a small pipeline with four stages: Org source, Pandoc conversion, a Hugo build and
a container image that ArgoCD deploys. The CI part is familiar from my sysadmin work.
The GitOps handoff was the new part for me.

* Writing

Every post is just a file, named like =org/this-file=. This post starts like this:

#+begin_src org
#+TITLE: How this site is built
#+DATE: 2026-10-02
#+FILETAGS: hugo:emacs:ci

Body text in Org.
#+end_src

I write in Org because I already use Emacs. The source stays plain text, and I never
hand-edit the generated HTML.

* Turning it into a website

A small script turns my files into the format the website builder needs:

#+begin_src shell
pandoc -s -f org -t markdown --wrap=none org/post.org \
  -o content/posts/post/index.md
#+end_src

The converter also maps =#+FILETAGS= to a Hugo =tags= list in the front matter, and
=#+ALIASES= to old-URL redirects. That is the only custom logic in the pipeline.

* Building and shipping

#+begin_src shell
hugo --minify    # Org -> HTML into public/
#+end_src

GitHub Actions runs on every push to =main=:

1. =scripts/convert.sh= turns =org/*.org= into =content/posts/*/index.md= with
   Pandoc.
2. =hugo --minify= builds =public/=.
3. The workflow builds the nginx image and pushes it to GHCR with a tag like
   =main-20261018-124657-c468611=.
4. It rewrites the image tag in =deploy/k8s/deployment.yaml=, pushes a branch and
   opens a pull request. This repo auto-merges that PR.

ArgoCD watches =main=, sees the manifest commit and syncs the Deployment. The
workflow has =contents: write= and =packages: write=, and no kubeconfig. Its only
path into the cluster is one image tag in git. A human gate would be a one-line
change: remove the =gh pr merge= step and require review on the tag PR.

* Four jobs, four tools

| Job        | Tool            |
|------------+-----------------|
| writing    | Org and Emacs   |
| conversion | pandoc          |
| build      | Hugo            |
| deploy     | GHCR and ArgoCD |

I like that each tool does one job. When something breaks, I can usually tell *where*
it broke. That has helped me more than any clever trick.

Now I had a place to write. The real work could start. The first thing that beat me
was secrets.
