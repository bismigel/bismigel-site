I wanted a place to write. I did not want to run a database, or learn a whole content
system. In the end, I got a few small steps that I mostly understand. I am writing
them down, so I can remember how they fit together.

* Writing

Each post is just a file. The name looks like =org/this-file=. This post starts like
this:

#+begin_src org
#+TITLE: How this site is built
#+DATE: 2026-10-02
#+FILETAGS: hugo:emacs:ci

Body text in Org.
#+end_src

I write in Org, because I already use Emacs. This way, I never have to deal with the
messy HTML underneath. There is probably a lot of Org that I do not use. It mostly
stays out of my way, and that is all I want.

* Turning it into a website

A small script turns my files into the format that the website builder wants:

#+begin_src shell
pandoc -s -f org -t markdown --wrap=none org/post.org \
  -o content/posts/post/index.md
#+end_src

I had to add one extra part, so that my tags show up as tags. I copied that part from
someone else, and I only half understand it. It works, so I have left it alone.

* Building and shipping

#+begin_src shell
hugo --minify    # Org -> HTML into public/
#+end_src

A robot runs the same steps every time I push:

1. turn the files into the website format
2. run the website builder
3. put the result into a small web server image
4. save the image and change the version number

Then ArgoCD sees the new version and updates the site. I never do it by hand.

There is one part I do not follow: how the robot's version number gets back into my
config, so that ArgoCD can see it. I set it up once, and it works. But I would have to
read it again before I touch it.

* Four jobs, four tools

| Job        | Tool            |
|------------+-----------------|
| writing    | Org and Emacs   |
| conversion | pandoc          |
| build      | Hugo            |
| deploy     | GHCR and ArgoCD |

I like that each tool does one job. When something breaks, I can usually tell *where*
it broke. That has helped me more than anything clever.
