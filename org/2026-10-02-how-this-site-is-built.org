I wanted a place to write. I did not want to run a database, or learn a whole content
system. So I built the site from a few small steps. I mostly understand them, and I am
writing them down so I can remember how they fit together.

* Writing

Every post is just a file, named like =org/this-file=. This post starts like this:

#+begin_src org
#+TITLE: How this site is built
#+DATE: 2026-10-02
#+FILETAGS: hugo:emacs:ci

Body text in Org.
#+end_src

I write in Org because I already use Emacs. That way I never have to touch the messy
HTML underneath. There is probably a lot of Org I do not use. It stays out of my way,
and that is all I want.

* Turning it into a website

A small script turns my files into the format the website builder needs:

#+begin_src shell
pandoc -s -f org -t markdown --wrap=none org/post.org \
  -o content/posts/post/index.md
#+end_src

One extra step makes my tags show up as tags. I copied it from someone else and
understand only half of it. It works, so I have left it alone.

* Building and shipping

#+begin_src shell
hugo --minify    # Org -> HTML into public/
#+end_src

A robot runs the same steps every time I push:

1. turn the files into the website format
2. run the website builder
3. put the result into a small web server image
4. save the image and change the version number

Then ArgoCD sees the new version and updates the site. I never do it by hand.

One part still confuses me: how the robot's version number gets back into my config so
ArgoCD can see it. I set it up once and it works. But I would have to read it again
before I touch it.

* Four jobs, four tools

| Job        | Tool            |
|------------+-----------------|
| writing    | Org and Emacs   |
| conversion | pandoc          |
| build      | Hugo            |
| deploy     | GHCR and ArgoCD |

I like that each tool does one job. When something breaks, I can usually tell *where*
it broke. That has helped me more than any clever trick.

Now I had a place to write. The real work could start. The first thing that beat me
was secrets.
